## Claude 설정

로컬 `.env`에 Claude 키를 연결했습니다. `.env.example`의 키 자리는 비워 둡니다. 공공데이터 API 키 설정은 아래 공식 API 연결 안내를 참고하세요.

```dotenv
ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=claude-sonnet-4-6
PORT=5184
```

발급받은 키를 **서버의 `.env`에만** 입력하고 Node 서버를 재시작합니다. `VITE_` 접두사를 사용하거나 브라우저 코드에 키를 넣지 않습니다. 키가 없으면 예시 질문 중심의 규칙 기반 체험으로 실행하며 화면에서 구분합니다. 키가 설정되면 Claude Messages API의 tool use로 질문을 구조화하고, 서버가 실제 카탈로그에서 검색·가격 계산·후보 검증을 수행합니다. API 실패 시 성공한 체험 응답으로 위장하지 않습니다.

공식 API 문서: https://platform.claude.com/docs/en/api/messages/create

Vercel에서는 프로젝트 Environment Variables의 `ANTHROPIC_API_KEY`에 키를 설정한 뒤 재배포합니다. 이번 로컬 변경으로 배포본의 환경변수는 바뀌지 않습니다. Claude 챗봇은 로그인 없이 사용할 수 있으며, IP당 분당 12회로 제한합니다.
모델 문서: https://platform.claude.com/docs/en/models/sonnet-4-6/overview

## 연관 검색

일반 검색과 AI 도우미의 상품 조회가 `shared/search.mjs`를 함께 사용합니다. `SEARCH_ALIASES`에서 돈까스/돈가스, 계란/달걀, 요거트/요구르트 등 검색용 표기를 관리합니다. 원본 상품명이나 원재료 제외 필터는 바꾸지 않습니다. 맛 표기는 음료 연결 부분에만 적용하고 맛살 등의 이름에서는 제거하지 않습니다.

브랜드·상품 단어의 순서가 달라도 모든 단어를 만족해야 검색합니다. 관련도순은 상품명·품목 일치를 우선하며, 가격·상품명 등의 명시적 정렬과 상세 필터도 계속 적용됩니다. 등록 상품에서 추출한 연관 검색어와 결과가 없는 경우의 오타 후보를 제공합니다. 제안은 사용자가 클릭할 때 적용되며 현재 필터는 유지합니다. 숫자 식별번호에는 오타 교정을 적용하지 않습니다. 이 기능은 규칙 기반 검색이며 의미를 자유롭게 해석하는 벡터 검색은 아닙니다.

## 데이터의 범위

`public/data/products.json`은 기존 엑셀 정리본 7,902건입니다. `market-enrichment.json`은 기존에 수집한 나라장터 가격·이미지 연결본입니다. 검색 목록은 수집본에 공통 저장소의 유효한 공식 조회 결과를 합쳐 사용합니다. 상품 상세에서는 별도의 공식 나라장터 API를 요청 시 조회하며, 영양 질문은 식약처 API를 사용합니다. 두 서비스의 개발계정 승인을 받고 로컬 서버의 실제 조회를 확인했습니다. PPT 분류표에 정확히 일치하지 않는 품명은 기타/분류 확인 필요로 남깁니다. 추후 제공되는 카테고리 엑셀로 대조할 수 있도록 매핑은 `shared/catalog.mjs`에 분리했습니다.

원본의 제조사 정보는 미제공이지만 공식 API에서 확인한 제조사를 공통 자료에 반영합니다. 아직 조회하지 않은 상품의 제조사 선택지는 제한됩니다. 계약업체를 제조사로 치환하지 않았습니다. 상품 상세의 추가 이미지는 `/api/product-images?id=물품식별번호`로 나라장터 공개 등록 목록을 조회하고 1시간 캐시합니다. 등록된 순서대로 썸네일과 확대 보기를 제공하며, 추가 사진 없음과 조회 실패를 구분합니다. 모든 추가 사진이 영양 라벨인 것은 아니며 원본 내용 확인이 필요합니다. 전체 카탈로그의 이미지 일괄 검증이나 OCR은 수행하지 않았습니다.

엑셀 원본에는 영양 기준 중량이 없어 그 수치는 원문으로 표시합니다. 보고번호가 일치한 공식 영양 자료는 100g/100mL/배식량으로 환산하여 필터·비교·추천·하루 영양 검증에 사용합니다. 일반 급식 상담은 AI 일반 안내로 구분합니다. 미제공 열량은 계산하지 않습니다. 식단 배식량은 기본 데모 설정이며 사용자가 변경할 수 있습니다. 기관 영양 기준과 출처도 입력할 수 있습니다. 음식의 역할·메뉴군은 상품명 기반 규칙입니다. 공식 조리법·표준 배식량·하루 영양 기준을 받으면 별도 테이블로 연결해야 합니다.

계획의 제외 재료는 원재료 원문 검색입니다. 원재료 미제공 상품은 제외 조건 적용 시 후보에서 뺍니다. 알레르기 안전성 판정은 아닙니다. 조건에 맞는 상품이 부족하면 누락 슬롯과 이유를 표시하고 발주 가져오기를 막습니다. 전체 구매금액은 포장 올림과 최소 주문량을 반영하며 배송비 등은 제외됩니다.

## 저장과 운영 범위

로컬 서버는 127.0.0.1에 바인딩합니다. 로컬 계정과 식단은 `.local/accounts.json`에 저장하며 세션은 서버 메모리를 사용합니다. Vercel에서는 서울 리전의 비공개 Blob 저장소에 계정·세션·식단을 저장하므로 함수 재시작 이후에도 기록과 유효한 로그인 세션을 유지합니다. 로컬과 배포본의 계정 저장소는 별개입니다. 비밀번호는 scrypt 해시로 저장하며 배포본 쿠키는 HttpOnly/SameSite/Secure를 사용합니다. `.env`, `.local`, 빌드 결과와 의존성은 Git과 배포에서 제외했습니다.

Vercel의 `BLOB_READ_WRITE_TOKEN`은 비공개 저장소를 연결할 때 서버 환경변수로 설정됩니다. 운영 서비스로 전환할 때는 운영용 DB와 인증·계정 복구·권한 관리·공유 요청/비용 한도를 보강해야 합니다. 현재는 시연용 계정 시스템이며 기관 계정과 연동하지 않습니다.

## 2026-10-15 식단 대화와 영양 근거

- 챗봇 식단 요청은 시뮬레이터의 기본 인원·기간을 자동 채우지 않습니다. 날짜·끼니·메뉴 개수를 보존하고 인원·선호·예산 등 누락 조건을 먼저 확인합니다.
- 아침 메인 1개·반찬 2개 요청은 해당 세 슬롯만 생성합니다. 후속 인원 변경에도 범위를 유지하며, 발주 예산은 선택한 끼니만 합산합니다.
- 근거 패널은 공공데이터의 보고번호 일치 자료를 배식량으로 환산합니다. 영양별 합계, 데이터 확인 개수, 최소 목표 대비 비율, 상한 사용률, 부족·초과량과 원자료를 표시합니다. 목표 미설정·누락 수치·일부 끼니의 하루 기준 비교는 충족으로 처리하지 않습니다.
- 예산/선호 기반 초안의 상품에 공식 영양 자료가 없으면 그 상태를 표시합니다. 영양 목표를 적용하는 생성은 검증된 영양 자료가 있는 후보만 사용하므로 미구성 항목이 생길 수 있습니다.
- 검색 버튼·Enter·Space로 검색을 실행하면 분류·가격·영양·업체 등 필터와 정렬·페이지를 초기화합니다. 한글 IME 조합 중에는 단축 검색을 실행하지 않습니다.

## 2026-10-15 Mili 대화 처리 개선

Claude 키가 설정되면 모든 메시지를 Claude가 문맥과 함께 해석합니다. 정규식으로 대화를 먼저 가로채던 방식은 키가 없는 체험 모드에서만 사용합니다. 설명·이유 질문·조건 확인은 자유 응답으로, 실제 상품 선택과 영양·금액 계산은 서버 검증으로 처리합니다.

- 확인된 날짜·끼니·구성·인원·취향·예산을 `chatContext`에 유지합니다. 설명 질문을 끼워 넣어도 조건이 사라지지 않으며, 이번에 바뀐 항목만 갱신합니다. 사용자 발언에 인용 근거가 없는 변경과 시뮬레이터 기본값은 확정 조건으로 채우지 않습니다.
- “백오십 명”, “오천 원 정도”, “아까 조건으로”, “인원만 이백 명으로” 같은 답변도 Claude가 해석합니다. 이미 확인한 항목은 질문 후보에서 제외하고 미확인 조건만 한 번에 1~2개 묻습니다. 자유 형식 선호와 제외 재료도 답변으로 인정합니다.

## 2026-10-15 챗봇 품질 재검증 — 로컬 수정

실제 Claude 대화에서 제외 조건 추가 누락, 같은 식단 재추천, 대화 초기화 후 이전 조건 잔류, 단순 가격 질문의 불필요한 영양 조회, 다른 상품 요청에 같은 상품을 다시 내놓는 문제를 확인하고 수정했습니다. 이번 변경은 로컬 데모에 반영했으며 위 운영 배포 이후의 변경입니다.

- 사용자 원문 근거는 발언별로 검증합니다. 여러 발언을 합친 인용도 각각 확인하고, 검증에 실패한 변경을 조용히 무시하며 완료했다고 말하지 않습니다.
- 식단 대안은 같은 조건 안에서 이전 메뉴군·상품을 피합니다. 후보 부족으로 이전 상품이 포함되면 경고를 표시합니다. 개별 상품 대안은 해당 품목에서 앞서 추천한 상품을 제외하며, 후보가 없을 때 같은 상품을 다시 추천하지 않습니다.
