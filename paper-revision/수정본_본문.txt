요   약
군 급식 조달에서는 상품 탐색, 식품정보 확인, 인원별 구매량 산정이 연속적으로 이루어진다. 본 연구는 이 과정을 연결한 MiliMarket 웹 프로토타입을 제시하고 UI 및 기능 흐름을 통해 설계 의도를 설명한다. 직접 검색과 대화형 지원을 병행하며, 조달 상품과 영양정보의 연결 근거를 확인하고 포장 단위 구매비용을 산정하도록 구성하였다. 핵심 기여는 정보의 확인 상태를 의사결정에 반영하고, AI의 조건 해석과 등록 자료에 근거한 계산을 분리하여 담당자가 최종 검토하도록 설계한 데 있다. 기존 데이터 관리·구매량 산정 연구와 적용 범위를 비교하고 후속 평가 과제를 제시한다.




1. 서론
군 급식 담당자는 상품의 원재료·영양정보·규격을 확인한 뒤 인원과 배식량에 맞는 구매량을 산정한다. 이때 상품 선택의 적합성뿐 아니라 서로 다른 자료의 연결 근거와 실제 구매단위를 함께 검토해야 한다. 본 연구는 이 판단 과정을 화면과 기능의 연결 문제로 정의한다.
MiliMarket은 상품 7,902건의 검색과 AI 상담·식단 계획을 발주 검토로 연결한 웹 프로토타입이다. 본 논문은 2026년 10월 31일 로컬 구현 기준이며, 시연 주소 https://milimarket-demo.vercel.app/와 최신 수정 범위에 차이가 있다.
2. 관련 연구
FoodCASE는 식품 성분·섭취·총식이조사 데이터의 관리와 연결을 지원한다[2]. FAO/INFOODS는 식품 연결 근거와 조리 상태 등의 확인을 강조한다[3]. 본 연구는 이 원리를 조달 상품과 식품정보의 대응 관계를 검토하는 과정에 적용한다.
USDA Food Buying Guide는 제공량·수율·구매단위에 따른 수량과 비용 산정을 다룬다[4]. 국내 군 급식 연구는 잔반 예측과 부식청구 최적화를 검증하였다[1]. 본 연구는 주어진 급식 조건에서 상품을 고르고 구매안을 검토하는 단계에 초점을 둔다.
3. 시스템 및 흐름 설계
3.1 UI 흐름과 화면 분리
그림 1은 주요 작업 경로이다. 검색 화면은 필터·상품 목록·발주 계산기를 함께 배치하여 후보 탐색과 수량 확인을 연결한다. 상세·비교 화면에서는 규격, 환산 단가, 영양 근거를 검토한다. AI 상담은 조건을 구체화하고 상품 상세 또는 식단 계획으로 연결한다. 익숙한 상품은 직접 찾고 복합 조건은 대화로 풀도록 진입 경로를 나누되, 최종 수량·금액 확인은 발주 검토 화면으로 모았다.

(그림 1) 직접 탐색과 대화·식단 지원의 UI 흐름
3.2 기능 처리와 근거 확인
그림 2는 입력부터 검토안 저장까지의 기능 흐름이다. 일반 검색은 띄어쓰기·동의어를 정규화하여 후보를 조회한다. 조달청 품목정보[5]는 물품식별번호로, 식약처 영양정보[6]는 품목제조보고번호로 연결하며, 출처·기준량·조회 시점을 함께 관리한다.

(그림 2) 근거 확인과 계산을 분리한 기능 흐름
영양 환산은 보고번호 일치 자료를 사용한다. 실시간 복수 후보는 보류하고, 일괄 매칭은 같은 번호의 후보를 상품명으로 좁혀 단일 자료를 채택한다. 10월 23일 수집본에서 2,102건을 연결하였다. 이름만 일치한 자료·기준량 누락·g과 mL 간 환산은 제외하며, 결측을 0이나 목표 충족으로 처리하지 않는다.
AI는 조건을 해석하고 서버는 상품·영양·금액을 검증한다. 부족한 조건은 추가 질문으로 보완한다. 식단은 기간·끼니·제외·반복 조건을 적용한다. 미구성 항목을 표시하고 채워진 상품만 발주 검토로 가져오며, 구매 후보가 없으면 차단한다. 식단은 계정별 최근 20건을 저장하고 검토안은 CSV로 내보낸다.
3.3 구매 수량과 비용 산정
인원 N, 1인 계획량 s, 판매단위 중량 W, 판매단가 P를 이용하여 구매 수량 Q와 예상 상품 금액 C를 구한다. 포장 올림은 기존 지침의 원리를 적용한다[4].
Q = ceil(N × s / W),     C = Q × P
s와 W의 단위·사용 기준을 맞추고 영양표시 기준량을 배식량으로 대체하지 않는다. 개수형 상품은 1인 제공수량으로 계산한다. 식단 구매목록에는 기간별 필요량을 합산해 포장 올림과 최소 주문량을 적용한다. 배송비는 제외하며, 프로토타입은 실제 주문을 전송하지 않는다.
4. 차별성과 설계 고찰
첫째, 나라장터의 계약·품목 조회 및 구매 기능[5]에 군 급식의 인원·배식량 검토 과정을 연결한다. FoodCASE[2]의 데이터 관리나 잔반 예측 연구[1]와 비교할 때, 본 연구의 기여는 탐색·근거 확인·구매량 산정을 담당자의 작업 순서에 맞춰 통합한 데 있다. 품목 중심의 조회 결과를 인원·배식량별 구매안으로 전환하는 것이 적용상 차별점이다.
둘째, 환산 단가가 낮아도 포장 올림 후 구매비용은 높아질 수 있음을 설계에 반영하였다. 가상 예로 1.2kg이 필요할 때 A(1kg·5,600원)는 2포장 11,200원, B(3kg·15,000원)는 1포장 15,000원이다. 따라서 단가 비교와 실제 필요량에 따른 비용 검토를 연결해야 한다. 독창성은 새 산식보다 비교 기준을 업무 흐름에 적용한 점에 있다.
셋째, 대화 편의성과 판단의 추적 가능성을 고려하였다. 조건 변경·대안 요청을 처리하고 대화·검색 상태를 브라우저에 보존한다. 영양 패널은 배식량별 합계, 목표 대비 부족·초과와 자료 누락을 표시한다. 출처별 목표는 수정 가능하며 기관의 공식 승인 기준은 아니다. 미확인 이유를 제시하고 최종 선택은 담당자에게 맡긴다.
검색·비교·식단·영양 근거·저장·CSV 출력은 구현하였다. PostgreSQL은 설계·적재 검증 단계로 앱과 미연동이다. 자동 검사는 보완이 필요하며 현장 효과는 미검증이다. 보고번호 일치 후에도 포장·표시 갱신을 확인해야 한다. 후속 평가는 검색, 비교 추가, 발주 계산 연결의 세 조건에서 과업 시간·수량 오류·자료 오사용을 비교하고 AI 효과와 식단 적합성을 검증한다.
5. 결론
본 연구는 검색·대화형 식단·영양 근거·포장 구매비용 계산을 통합한 웹 프로토타입을 구현하였다. 식단 저장과 검토안 출력까지 연결하며 실제 주문은 전송하지 않는다. 향후 자동 검사 보완, 운영 DB 연동과 사용자·현장 평가로 안정성과 업무 효과를 검증한다.
